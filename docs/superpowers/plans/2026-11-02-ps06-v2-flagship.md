### 2.3 Orchestrator (`app/agent/orchestrator.py`) + verifier (`app/agent/verifier.py`)
- [x] **Planner:** LLM `TASK: plan_steps` → returns `{"steps": [{thought, tool, args}, …]}` (2–5 steps). MockLLM deterministic planner: heuristic goal→tool selection (e.g. goal mentions "eligibility"/"apply" → inspect_profile + rank_jobs + propose_hitl_approval).
- [x] **Executor:** runs steps sequentially; each step's JSON output is merged into a working-memory dict keyed by tool name; a step output is available to later steps.
- [x] **Verifier:** `verify_claim_ids(text_or_json, ctx)` extracts every `job-\d+`, `course-\d+`, `skill_id`, `SOP-\d+`, `run-\d+` reference and confirms it exists in DB/data; returns `(verified_refs, stripped_refs)`. `final_answer` is passed through the verifier; unverified claims are flagged/stripped and recorded.
- [x] **Recovery:** per-step try/except. On failure: retry once with a repair prompt (`TASK: repair_step`); if still failing or LLM raises/timeouts/malformed-JSON → fall back to deterministic path, set `AgentStep.error_recovered` and `AgentRun.fallback_triggered=True`. **Never** raise a 500 — return a completed/failed `AgentRun` with a human-readable `final_answer`.
- [x] `run_agent(ctx, session, *, goal, student_id=None, actor_role="student") -> AgentRun` persists `AgentRun` + `AgentStep` rows (flush run first) and returns the run (with steps) for serialization.
